# ADR 0008: 長い会話と次段階のマルチモーダル入力

## 状態

採用。

## 決定

- SQLite 上の会話履歴は保持したまま、Chat API に送るテキスト量を直近から最大約 14,000 文字に制限する。サーバーがコンテキスト超過を返したら、その質問だけで一度再試行する。履歴を消す操作は不要にする。
- Gradio はチャコールとフューシャを基調にし、モードや検索の設定、マスク、システム状態を閉じた欄へまとめる。会話欄と添付操作を主役にする。
- 4 枚生成の兄弟を同じストリップに並べ、既定は var1 を選択する。選択画像と「N枚目」の指示は編集の親画像に反映する。
- [固定版の `QwenImage21Pipeline`](https://github.com/huggingface/diffusers/blob/e0abab83b5df05de9e7abd788643c1a7c1e42e28/src/diffusers/pipelines/qwenimage21/pipeline_qwenimage21.py) にマスク専用引数がないため、ローカル編集では赤い領域プレビューと二値マスクを追加の参照画像として渡し、編集領域を指示文でも指定する。画素単位の保持は保証されない。HTTP ワーカーへは `mask` を明示的に渡す。
- 動画は `ffprobe` で長さと容量を確認してから `ffmpeg` で最大 8 枚を抽出する。履歴には先頭フレームだけを通常の画像として残す。動画生成モデルは追加しない。
- 読み上げは `edge-tts` を必要時だけ使う。CPU と外部ネットワークを使い、失敗時も回答を残す。モックでは短い WAV を返す。
- リモート画像 URL が設定された場合は `HttpImageModel` を登録し、ローカル Diffusers の import とロードを避ける。API 契約は `docs/image-http-api.md` に固定する。

## 制約

GPU 上のマスク品質、動画 Vision の精度、リモートワーカー本体の運用はこの変更では未検証。4 枚の HTTP 生成も UI 側で逐次処理する。
