# ADR 0007: 画像系譜、複数参照、PDF、バリエーション、音声入力

## 状態

採用。

## 背景と決定

既存の Chat と画像生成の二モデル構成、SQLite と Drive の履歴保存、検索とコンテンツ方針を維持し、入力と画像操作を拡張する。

- 画像選択はセッション内の画像 ID で保持する。系譜ストリップは選択画像の root から現在の revision までを表示する。`元に戻す` は root のピクセルを新しい `edited` レコードへ複製し、直前の画像を親にする。画像モデルは起動しない。古い画像を選んだ編集はそこから新しい枝を作る。
- 複数画像を添付した編集では、添付順に最大 10 枚を条件画像へ渡す。系譜で選択した画像があれば最後に置く。最後の画像が編集のアスペクト比を決める。上限を超える画像は状態に通知し、条件画像には含めない。
- PDF は `pypdfium2` で最大 30 MB、先頭 6 ページまでを画像化する。縦長画像は重なりのある帯へ分割して Vision に渡し、履歴には元の画像だけを残す。PDF の各ページは通常のアップロード画像として履歴に残す。
- 画像生成のバリエーションは既定 1 枚、指定時 4 枚。最初の seed から 7919 ずつ増やし、GPU メモリを競合させないよう逐次実行する。結果は一つの assistant メッセージに保存する。編集には展開しない。
- 音声は `faster-whisper` の `small`、日本語指定、CPU 既定で必要時に読み込む。文字起こしをユーザーメッセージに含める。モックモードでは固定の文字列を返す。

## 影響

PDF、音声、4 枚生成には処理時間と追加依存が生じる。PDF は 6 ページで打ち切られ、長い縦長画像も帯の枚数に上限がある。ASR を CPU で実行するため GPU の常駐モデルは増えない。GPU や実際の Colab による性能確認は別途行う。
